# 常见问题与排障

[返回首页](../README.md)

先保留固件版本、构建日志末尾、串口 `status` 和故障发生时间。
分享日志前移除账户信息、主机标识及其他隐私；不要上传整个 Flash/NVS 备份或 Token。

## 配额一直是 86，或不随 Codex 变化

固件初始未知值是 `-1`，没有固定 86% 的演示模式。
本文配图中的 86% 是示例；设备上的固定数字可能是上一次主机下发后保存在 NVS 的值。

1. 确认 Mac 桥接程序正在发送真实数据；单独烧录固件不会连接 Codex 账户。
2. 发送 `status`，分别看 `week`、`five_hour`、`ble` 和 `connected`。
3. 检查快照是否有正确的 `PROTOCOL=codex-pet/1`，以及成对的 `WEEK`、`FIVE_HOUR`。
4. 确认发送的是“剩余百分比”，不是已用百分比或 0–1 的小数。
5. 需要隔离测试时，可手动发送 `quota 50 50` 检查显示变化；这是测试值，
   会改变并可能持久化设备数据，之后应恢复正常同步。不要把测试值当成修复。

## Codex 一直 READY，实际任务已经开始

固件只显示主机下发的状态，不会自行推断任务。
检查任务运行时主机是否发送了 `STATE=running`，以及设备是否回复 `OK state Running`。
可用 `state running` / `state ready` 做显示链路测试。
如果测试能切换，重点排查主机任务检测、快照更新和连接，而不是时钟绘制。
主机断连超时只自动把 WORKING 退回 IDLE，不会把所有 READY 状态改为 IDLE。

## 工作时没有动画，或动画卡顿

- 检查实际状态是否为 running，屏幕是否唤醒。
- 如果此前启用过减少动态效果，发送 `reduced_motion 0` 可恢复；它会保存设置。
- 查启动日志中动画缓存/画布分配是否失败。工作波前依赖 PSRAM 缓存和局部 DMA 更新，
  分配失败可能退回全帧路径。
- BLE 重连扫描、大量串口输出、频繁全画面重绘可能影响实际流畅度。
- 16ms 是调度目标，不代表已经测得 60fps。软件示意图无法验证实际帧率。

报告性能问题时附设备视频、版本和当时的主机同步频率，避免只凭单张图判断。

## 天气没有显示、变暗或位置不对

- 主机必须同时发 `WT`、`WC`、`WD`、`WU` 四个字段。
- 温度应为整数摄氏度，天气码为 0–99；不完整或超出范围的输入不会更新。
- “余杭”是固定标签，不是自动定位结果；主机天气查询也必须配置杭州余杭。
- 同步时间有效且天气超过 3 小时未更新会变暗，表示旧数据，不能只靠重新点亮屏幕解决。

## TIME SYNC、时间偏移 8 小时或日期不对

检查 `clock` 命令 / `E` 字段是否为**秒级 UTC 时间戳**，而非毫秒。
杭州时区偏移为 28800 秒，每次快照带上 `TZ=28800`。
有有效 RTC 数据时会尝试恢复时间；这不能替代主机对时间与时区的正确同步。

## CPU 或内存不显示

`CPU` 和 `MEM` 要成对出现；未知值为 -1，界面显示 `--`。
这两个值是 Mac 端提供的使用百分比，不是固件自行测量，也不持久化到 NVS。
不同系统工具的 CPU/内存统计口径可能不同，先核对主机实现再比较数字。

## 熄屏后没自动连接，或不能唤醒 Mac

显示休眠与 BLE 分开管理：仍连接时可以保留链路；约 5 分钟重连失败后会暂停 BLE 并熄屏。
先唤醒表盘，再确认主机广播和 `BLE host ready` 日志。
触摸只发送 `activate`，主机需要实现相应行为。若 Mac 已深度休眠、关机或 BLE 已断，
不能承诺此功能仍有效。`EVENT activate` 日志也不等于 Mac 已成功处理动作。

## 编译、端口或烧录失败

| 现象 | 安全检查 |
| --- | --- |
| 找不到 PlatformIO | 激活项目 `.venv`，确认 `pio --version` 是预期版本 |
| 依赖无法下载 | 检查网络/代理，保留固定提交，不随意换成最新库 |
| 找不到设备端口 | 更换支持数据的线，插拔对比 `pio device list`，核实设备而非猜端口 |
| 串口忙 | 关闭使用该端口的监视器/桥接进程，再尝试烧录 |
| 连不上芯片 | 按设备的正确下载模式流程处理，别改板型或擦除整片来碰运气 |
| 刷后无显示 / 画布失败 | 核对硬件、16MB/PSRAM 配置和启动日志；停止反复刷不同硬件配置 |

`firmware.bin` 不是整片备份。不要直接按地址 0 写入，也不要把其他设备的备份作为恢复镜像。
本包只有编译验证；独立包的硬件运行尚未再次验证，详见 [验证记录](verification.md)。
